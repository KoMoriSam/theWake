> [!IMPORTANT]
> This article is for learners of Sinhala who have questions about Sinhala typography.

When reading a Sinhala document, you may have encountered this: the text looks perfectly normal on screen, but turns into Latin letters and symbols when copied into another application. Or the same document looks different on different computers.

This usually does not mean the text is corrupted. The document may be using **legacy font encoding**.[^1]

## 1. Different ways of storing text

Compare these two examples:

- [[ශ්‍රී ලංකාව ඉන්දියන් සාගරයේ පිහිටි දූපතකි.]{.font-abhaya}  
 [Standard Unicode text]{.tooltip-content .font-sans}]{.tooltip .md:tooltip-right}

- [[› ,xldj bkaÈhka id.rfha msysá ¥m;ls\']{.font-abhaya-legacy .[&:is(:hover,:active)]:font-mono} [^2]  
 [Legacy-encoded text]{.tooltip-content .font-sans}]{.tooltip .md:tooltip-right}

Both display the same Sinhala sentence. But when copied into an environment without the corresponding legacy font, the second may still appear as Latin letters and symbols.

Although the two versions can produce the same glyphs, the character data stored underneath is completely different.

Before computers widely supported Unicode, many Sinhala fonts used ASCII and other single-byte character positions to hold Sinhala glyphs. FM Abhaya, FM Malithi, FM Gemunu and DL-Manel are examples of these non-Unicode legacy fonts.

The fonts do not change the characters stored in the text. They simply display what would otherwise be Latin letters or symbols as Sinhala glyphs. Correct display therefore depends on using the appropriate font and character mapping.

Unicode uses standardized character encoding. For example, `ක` is U+0D9A and `ෙ` is U+0DD9. A font renders these characters or character sequences as glyphs; it does not determine the encoded meaning of the text.

In other words, **Unicode text can change fonts without changing its characters, whereas legacy text needs a specific font mapping to display correctly.**

Converting legacy text to Unicode therefore requires changing the actual character data, rather than simply changing the font.

## 2. Why not just replace characters one by one?

Sinhala legacy font encodings do not always follow the logical order in which letters are constructed. To accommodate older typesetting systems, some characters are arranged according to the visual positions of their glyphs. Conjuncts, prenasalized consonants and other special forms may use dedicated character positions or be assembled from several glyph fragments.

Unicode works differently: text is stored as characters and their combinations, while the font shaping system handles glyph positioning, joining and substitution. Conversion therefore involves **reordering, recognizing combinations, reconstructing glyph sequences and resolving encoding ambiguities**, as well as character mapping.

These examples illustrate several different conversion problems:

1. **Visual order differs from logical order.**  
   The input order in the legacy encoding can be the reverse of Unicode storage order.
2. **Different encoded sequences can represent the same glyph.**  
   Some zero-width markers in legacy text only control visual presentation and have no independent textual meaning. Different character arrangements can therefore produce the same result. A converter needs to recognize these equivalent sequences and normalize them to the corresponding Unicode combinations.
3. **Special glyphs can be assembled visually.**  
   Legacy encodings can combine fragments such as [\`]{.font-abhaya-legacy}, [C]{.font-abhaya-legacy}, [F]{.font-abhaya-legacy} and [J]{.font-abhaya-legacy} to produce the same appearance as a dedicated glyph. For example, both [Õ]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} and [\`.]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} correspond to [ඟ]{.font-abhaya}; both [\[]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} and [\`Co]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} correspond to [ඤ]{.font-abhaya}.
4. **The same legacy encoding can correspond to different Unicode structures.**  
   Prenasalized consonant letters such as [ඟ]{.font-abhaya}, [ඦ]{.font-abhaya}, [ඬ]{.font-abhaya} and [ඳ]{.font-abhaya} have their own code points. Traditional conjuncts, by contrast, are generally represented by consonants, the virama ([්]{.font-abhaya}) and the zero-width joiner (ZWJ). Although related in articulation and appearance, they are different letter structures and cannot simply be interchanged. For example, legacy [\`c]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} may correspond to [ඦ]{.font-abhaya} or to [ඤ්‍ජ (ඤ්ජ)]{.font-abhaya}. Because legacy font encoding does not fully distinguish these structures, character replacement alone cannot resolve the ambiguity; context and orthography must also be considered.

A reliable converter therefore needs more than a simple character lookup table. It must recognize complete glyph combinations in the legacy encoding, re-encode them according to Unicode character structures, and apply explicit rules when ambiguity remains.

## 3. Mixing Sinhala and English

Real documents rarely contain only Sinhala. English names, Arabic numerals, URLs and other symbols often occur in the same passage.

For example:

- [[Zoom Link එක මේ Group එකට යොමු කරනවා.]{.font-abhaya}  
 [Standard Unicode text]{.tooltip-content .font-sans}]{.tooltip .md:tooltip-right}

- [[[Zoom Link]{.font-abhaya .group-[&:is(:hover,:active)]:font-mono} [tl fï]{.font-abhaya-legacy .group-[&:is(:hover,:active)]:font-mono} [Group]{.font-abhaya .group-[&:is(:hover,:active)]:font-mono} [tlg fhduq lrkjd\']{.font-abhaya-legacy .group-[&:is(:hover,:active)]:font-mono}]{.group} [^2]  
 [Legacy-encoded text]{.tooltip-content .font-sans}]{.tooltip .md:tooltip-right}

In this sentence, [tl]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy}, [fï]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy}, [tlg]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy}, [fhduq]{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} and [lrkjd\']{.font-mono .[&:is(:hover,:active)]:font-abhaya-legacy} represent Sinhala, while [Zoom Link]{.font-mono .[&:is(:hover,:active)]:font-abhaya} and [Group]{.font-mono .[&:is(:hover,:active)]:font-abhaya} should remain unchanged.

Mixed text therefore requires contextual judgment. Replacing every Latin character unconditionally will not work. Without clear boundaries, some ambiguities may be impossible to resolve fully automatically.

## 4. What can the Sinhala Font Encoding Converter do?

This site's [Sinhala Font Encoding Converter](https://komori.cc/tools/sinhala-font-converter) supports conversion in both directions between standard Unicode and legacy font encoding.

Legacy font encodings generally arrange characters according to glyph positions, whereas Unicode uses standardized character encoding and logical order. Conversion must therefore recognize and reconstruct vowel signs, consonant conjuncts and special glyph forms, rather than merely replace characters.

Converting legacy text to Unicode removes the dependency on a particular legacy font and makes copying, searching, web display, database storage, machine translation and natural language processing easier. Conversion in the other direction produces the encoding needed by legacy fonts for documents and typesetting workflows that still use them.

The converter mainly handles:

- **Vowel signs (පිලි):** Recognizing positions, combinations and variants, reordering characters, and handling compound vowels and special stacked forms.
- **Consonant conjuncts (බැඳි අකුරු):** Supporting traditional conjuncts still used in modern Sinhala, along with complex conjuncts and touching forms (ස්පර්ශ අකුරු) in Pali, classical texts and traditional typography. Options allow different forms to be normalized or preserved.
- **Prenasalized consonants and dedicated glyphs:** Handling dedicated encodings for letters such as ඟ, ඦ, ඬ and ඳ (සඤ්ඤක අක්ෂර), as well as compact forms of some combinations containing ද.
- **Consonant abbreviations (ව්‍යඤ්ජන නියෝජක සංකේත):** Handling යංශය, රකාරාංශය and රේඵය separately, with options to preserve, normalize or expand them.
- **Pali orthographic conversion:** Supporting traditional Pali vowel conventions by converting ඒ, ඕ and their corresponding vowel signs to එ and ඔ forms, without changing the default conversion of ordinary Sinhala text.
- **Mixed-language text:** Identifying Sinhala segments in mixed encodings while preserving English, numbers and other content that does not need conversion as far as possible.
- **Nonstandard encoding order:** Accommodating some alternative input orders found in older documents and normalizing equivalent glyph combinations into standard Unicode sequences.

**There is no single standardized character mapping for legacy font encodings.** Different font families, and even different fonts within a family, may use different mappings. This site's converter currently implements rules primarily for the FM font system; compatibility with every legacy font is not guaranteed.

Some legacy encodings also contain overlapping character mappings, lost glyph information or ambiguities in mixed text. Certain traditional touching forms cannot be preserved completely through conversion in both directions. Results therefore still need to be checked against the original and the intended typesetting requirements.

## 5. Are legacy fonts still useful?

For new Sinhala documents, Unicode should generally be the first choice. Modern operating systems and browsers widely support Sinhala display and shaping, with fonts such as Abhaya Libre, Noto Sans Sinhala and Noto Serif Sinhala available.

Legacy fonts nevertheless retain practical value. Some historical documents, early electronic publications and existing typesetting projects depend on older FM, DL and similar encodings. Understanding how these encodings work is often necessary to read and preserve such material correctly.

If you only want the traditional visual style of an FM font without using its legacy encoding, consider a corresponding Unicode version. Pitaka.lk provides Unicode versions of some traditional font designs, though their licensing terms should still be checked before use.
